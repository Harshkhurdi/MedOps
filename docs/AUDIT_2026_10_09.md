# MedOps functional and security audit — 9 October 2026

## Result and scope

The audited manual workflows pass 161 tests: 87 unit/document, 52 isolated PostgreSQL integration, and 22 Chromium browser scenarios. The browser audit loads all 51 configured registers, 17 dedicated screens and 16 operational read endpoints, and verifies anonymous denial for the registers and operational APIs. Core lifecycle tests cover both manually created and Tender Tracker-imported tenders through the downstream operations and finance workflows.

Synthetic business records and files are confined to a separate local `medops_test` PostgreSQL 18 database. Production business data was not used for destructive tests. Astra coordinated the initial audit with GPT-6.1 Sol high workers; the primary chat completed fixes, release checks and additional Sol high review after the coordination run was interrupted.

## Validation

- Unit/document suite: 87 passed; tests inspect DOCX XML, PDF output, XLSX cells and ZIP members.
- Database suite: 52 passed using the isolated local database, including concurrency, immutable history, corrections, source review and mixed-product reporting.
- Complete browser suite: 22 passed, including manual/imported A–E lifecycles, service coverage UI, source prefill, same-register search, stale-response handling, document reset, email retry, access denial and login privacy.
- Additional production-mode browser suite: all 13 read/UI/security scenarios passed against the optimized build, including all 51 registers and the new UI regressions. These repeat checks are not added to the 161 unique-test count.
- TypeScript, ESLint, Prisma schema validation and optimized production build passed.
- All 11 migrations replayed in a fresh local database with no schema difference. Production migration history was inspected read-only: all 11 are applied. No migration is added by this audit.
- The existing dedicated MedOps Blob store is active in Mumbai and explicitly Private.
- Production dependency scan: zero advisories. Development-tool scan: five high entries in the ESLint → fast-glob → micromatch → braces chain. The registry still supplies braces 3.0.3; the suggested framework downgrade was not applied.
- Changed-file secret-pattern scan and Git whitespace checks passed. Environment files, credentials, test records and local storage are excluded from publication.

An optional `MEDOPS_E2E_PRODUCTION=1` mode runs browser tests against an already-built server. Use it for the read/UI suite below. The complete file-generation/upload workflows use the local development storage adapter; production correctly requires private object storage.

```sh
npm test
npm run test:integration
npm run test:e2e
npm run typecheck
npm run lint
npm run db:validate
npm run build
MEDOPS_E2E_PRODUCTION=1 npm run test:e2e -- audit-coverage.spec.ts ui-audit.spec.ts login-privacy.spec.ts sidebar.spec.ts
```

## Operating limits

Real email delivery, external AI responses, the private OCR worker and third-party tender availability were not invoked for this audit. Their consent, disabled/unconfigured states and appropriate mocked contracts are covered; live service acceptance needs valid operator configuration. Direct Tally/Zoho synchronization remains unavailable; accounting CSV/XLSX interchange is covered.

Chromium desktop/mobile layouts were tested, not every browser or load condition. Real company templates, signatures, recovery infrastructure and off-site backup procedures require operator acceptance. Backup failure paths were regression-tested; a complete off-site production disaster recovery exercise was not performed. Authenticated live business-screen acceptance depends on an existing employee login; this release's destructive and synthetic acceptance remains local.

Deployment identity, public production checks and screenshots are recorded in the user-facing release report accompanying this audit.
